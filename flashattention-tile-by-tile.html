§1

Overview

Earlier attention speedups cut floating-point operations (FLOPs) with sparse or low-rank approximations. Many of them ran no faster in wall-clock time. The authors argue that attention must be IO-aware, where IO means input/output between memory levels. On a modern graphics processing unit (GPU), attention is limited by memory reads and writes, not by arithmetic.

The bottleneckStandard attention writes the N×N score matrix to slow off-chip high-bandwidth memory (HBM). It then reads the matrix back, several times. For long sequences, these HBM accesses dominate runtime and memory.
The fixSplit Q, K and V into blocks that fit in fast on-chip static random-access memory (SRAM). One fused kernel runs matmul → softmax → matmul block by block. The N×N matrix never exists in HBM.
The enabling mathSoftmax needs a whole row, but each step sees only part of one. Online softmax keeps a running max and sum per row. It rescales earlier partial results whenever a larger score appears. The answer is exact.
Backward passStore only the output O and two numbers per row. Recompute the attention tiles during the backward pass. The extra FLOPs cost less time than the HBM accesses they replace.

The result is exact attention (not an approximation) with O(N) extra memory. HBM accesses drop from Θ(Nd + N²) to Θ(N²d²/M), where M is the SRAM size.

§2

Attention

For one attention head, the inputs are three matrices \(\mathbf{Q}, \mathbf{K}, \mathbf{V} \in \mathbb{R}^{N\times d}\). Here N is the sequence length and d is the head dimension. Attention is defined as:

\[ \operatorname{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \operatorname{softmax}\!\Big(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d}}\Big)\,\mathbf{V} \]

Softmax applies to each row of its argument. Computed in stages, attention produces two N×N intermediates, the scores S and the probabilities P:

\[ \underbrace{\mathbf{S}}_{N\times N} = \frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d}}, \qquad \underbrace{\mathbf{P}}_{N\times N} = \operatorname{softmax}(\mathbf{S}), \qquad \underbrace{\mathbf{O}}_{N\times d} = \mathbf{P}\mathbf{V} \]

Row \(i\) of the output averages the value vectors, weighted by how well query \(i\) matches each key:

\[ \mathbf{o}_i \;=\; \sum_{j=1}^{N} \frac{e^{s_{ij}}}{\sum_{k} e^{s_{ik}}}\, \mathbf{v}_j , \qquad s_{ij} = \frac{\mathbf{q}_i^\top \mathbf{k}_j}{\sqrt{d}} . \]

The head dimension \(d\) is small, 64 or 128, while \(N\) runs from 1K to 64K or more. At N = 4096 in 16-bit floating point (fp16), one head's S takes 32 MiB. With 16 heads and a batch of 8, one layer's S takes 4 GiB.

The rest of this page omits the factor \(1/\sqrt{d}\), masking and dropout. The paper's Algorithm 2 adds them back with the same structure. Each (batch, head) pair is an independent problem.

§3

The GPU memory hierarchy

The paper runs on an NVIDIA A100 GPU. Its memory has two levels, and the programmer moves data between them explicitly.

Streaming multiprocessors, HBM and kernels

  • Streaming multiprocessor (SM): one of the GPU's many processors; the A100 has 108. Each SM has compute units, including Tensor Cores for matmul, plus registers and 192 KB of SRAM.
  • HBM: the large off-chip memory where tensors live. nvidia-smi reports it as GPU memory.
  • Kernel: one GPU function launch, such as one PyTorch op. It loads inputs from HBM, computes, and writes outputs back to HBM. Consecutive kernels exchange data only through HBM.

For a CPU programmer, SRAM resembles an L1 cache that the kernel manages by hand. The kernel decides what to load and when. FlashAttention applies cache blocking, the idea behind tiled matrix multiplication, to attention. Softmax is the part that needs a new idea.

Compute-bound vs. memory-bound

An operation's arithmetic intensity is the FLOPs it performs per byte it moves. The A100 delivers about 312 TFLOP/s of fp16 Tensor Core math, but HBM supplies only 1.5–2.0 TB/s. An op therefore needs roughly 150–200 FLOPs per byte to become compute-bound.

Large matmuls and convolutions with many channels reach that intensity, so they are compute-bound. Elementwise ops such as dropout and masking are memory-bound, and so are reductions such as softmax and layer norm. They do a few FLOPs per element and run only as fast as HBM feeds them.

Even \(\mathbf{QK}^\top\) sits below the threshold. It does \(2N^2d\) FLOPs and writes \(N^2\) fp16 outputs, or 2N² bytes. Its intensity is therefore about d, or 64–128 FLOPs per byte. Softmax, masking and dropout on S fall far lower.

Key idea · kernel fusion

When several ops touch the same data, kernel fusion loads it from HBM once, applies all the ops in SRAM, and writes once. Compilers already fuse elementwise chains this way. Training complicates fusion, because the backward pass needs the intermediates. The usual approach writes them to HBM anyway. FlashAttention fuses all of attention and still stores no N×N intermediate.

§4

Standard attention is bound by memory traffic

The paper calls the textbook implementation Algorithm 0. Each line is a separate kernel, and each kernel round-trips through HBM:

Algorithm 0 Standard attention. Q, K, V ∈ ℝN×d in HBM.
Load Q, K by blocks from HBM, compute S = QKᵀ, write S to HBM. // N² written Read S from HBM, compute P = softmax(S), write P to HBM. // N² read + N² written Load P and V by blocks from HBM, compute O = PV, write O to HBM. // N² read Return O.

The forward pass moves about 4Nd + 4N² elements, and the N² terms dominate because N ≫ d. Each added masking or dropout kernel adds another N² read and write. Training also stores P, one N×N matrix per head, for the backward pass. That is why memory grows quadratically.

The paper profiles GPT-2 attention in PyTorch (its Figure 1, right). The matmuls take less time than the memory-bound mask, softmax and dropout kernels. A fused FlashAttention kernel runs 7.6× faster than that pipeline.

§5

The mathematics of tiled attention

Tiled attention rests on three facts from basic math.

Fact 1. Online softmax: statistics merge across sub-vectors

Let \(\mathbf{x} \in \mathbb{R}^n\) be a vector. Define its max \(m\), its shifted exponentials \(f\), their sum \(\ell\) and its softmax:

\[ \begin{aligned} m(\mathbf{x}) &= \max_i x_i, &\qquad f(\mathbf{x}) &= \big[e^{x_1 - m(\mathbf{x})}, \ldots, e^{x_n - m(\mathbf{x})}\big], \\[4pt] \ell(\mathbf{x}) &= \sum_i f(\mathbf{x})_i, &\qquad \operatorname{softmax}(\mathbf{x}) &= \frac{f(\mathbf{x})}{\ell(\mathbf{x})} . \end{aligned} \]

Subtracting the max keeps every exponent at or below 0. Without it, \(e^{x_i}\) overflows 16-bit floats once \(x_i\) exceeds about 11.

Split \(\mathbf{x}\) into two sub-vectors, \(\mathbf{x} = [\mathbf{x}^{(1)}, \mathbf{x}^{(2)}]\), each with its own \((m, \ell)\). The statistics of the whole vector follow exactly:

\[ \begin{aligned} m(\mathbf{x}) &= \max\!\big(m(\mathbf{x}^{(1)}),\, m(\mathbf{x}^{(2)})\big) \\[2pt] f(\mathbf{x}) &= \big[\, e^{m(\mathbf{x}^{(1)}) - m(\mathbf{x})}\, f(\mathbf{x}^{(1)}),\;\; e^{m(\mathbf{x}^{(2)}) - m(\mathbf{x})}\, f(\mathbf{x}^{(2)}) \,\big] \\[2pt] \ell(\mathbf{x}) &= e^{m(\mathbf{x}^{(1)}) - m(\mathbf{x})}\, \ell(\mathbf{x}^{(1)}) \;+\; e^{m(\mathbf{x}^{(2)}) - m(\mathbf{x})}\, \ell(\mathbf{x}^{(2)}) \end{aligned} \]

Each sub-vector's exponentials are relative to its own max. The factor \(e^{m(\mathbf{x}^{(k)}) - m(\mathbf{x})} \le 1\) moves sub-vector k to the shared max.

The rule chains. A running \((m, \ell)\) merges with one new sub-vector at a time, so a vector of any length needs two scalars of state.

Each sub-vector's slice of the final softmax is its own \(f\) times one scalar:

\[ \operatorname{softmax}(\mathbf{x})^{(k)} \;=\; \underbrace{\frac{e^{m(\mathbf{x}^{(k)}) - m(\mathbf{x})}}{\ell(\mathbf{x})}}_{\text{one scalar}}\; f\big(\mathbf{x}^{(k)}\big) \]

For example, split \(\mathbf{x} = [1, 3, 2, 5]\) into \([1, 3]\) and \([2, 5]\):

\[ \begin{aligned} {[1, 3]}:&\quad m = 3, \quad \ell = e^{-2} + e^{0} = 1.135 \\ {[2, 5]}:&\quad m = 5, \quad \ell = e^{-3} + e^{0} = 1.050 \\ \text{merged}:&\quad m = 5, \quad \ell = e^{3-5}\cdot 1.135 + e^{5-5}\cdot 1.050 = 1.203 \\ \text{direct}:&\quad m = 5, \quad \ell = e^{-4} + e^{-2} + e^{-3} + e^{0} = 1.203 \end{aligned} \]

Fact 2. Block matrix multiplication and tiling

Let \(\mathbf{C} = \mathbf{A}\mathbf{B}\), with \(\mathbf{A}\) of shape m×n and \(\mathbf{B}\) of shape n×p. Cut all three matrices into blocks. The cuts along the shared dimension n must match between A's columns and B's rows.

The block rule. Each block of C is a sum of block products. It is the scalar rule cij = Σk aikbkj with blocks in place of numbers:

\[ \mathbf{C}_{ij} = \sum_k \mathbf{A}_{ik}\,\mathbf{B}_{kj} \]

The strip form. Row strip i of A is the row of blocks Ai1, Ai2, …. Join them side by side into one matrix \(\mathbf{A}'_i\). Column strip j of B is the column of blocks B1j, B2j, …. Stack them into one matrix \(\mathbf{B}'_j\). The sum then becomes a single product:

\[ \mathbf{C}_{ij} = \mathbf{A}'_i\,\mathbf{B}'_j, \qquad \mathbf{A}'_i = \begin{bmatrix} \mathbf{A}_{i1} & \mathbf{A}_{i2} & \cdots \end{bmatrix}, \quad \mathbf{B}'_j = \begin{bmatrix} \mathbf{B}_{1j} \\ \mathbf{B}_{2j} \\ \vdots \end{bmatrix} \]

Tiling. The block rule also gives a loop. Every product \(\mathbf{A}_{ik}\mathbf{B}_{kj}\) has the shape of \(\mathbf{C}_{ij}\), so the block can start at zero and absorb one product per iteration:

\[ \mathbf{C}_{ij} \;\leftarrow\; \mathbf{C}_{ij} + \mathbf{A}_{ik}\mathbf{B}_{kj}, \qquad k = 1, 2, \ldots \]

Each iteration loads one block of A and one block of B into fast memory. It multiplies them, adds the product to the accumulator, and drops the two blocks. The working set stays the same size however many terms the sum has. This technique is called tiling.

Fact 3. Row scaling passes through a product and a sum

Let \(\mathbf{A} \in \mathbb{R}^{m\times n}\) be a matrix with rows \(\mathbf{a}_1, \ldots, \mathbf{a}_m\). To scale row i by a number \(d_i\), multiply on the left by the m×m diagonal matrix \(\mathbf{D} = \operatorname{diag}(d_1, \ldots, d_m)\). For m = 3:

\[ \mathbf{D}\mathbf{A} = \begin{bmatrix} d_1 & & \\ & d_2 & \\ & & d_3 \end{bmatrix} \begin{bmatrix} \mathbf{a}_1 \\ \mathbf{a}_2 \\ \mathbf{a}_3 \end{bmatrix} = \begin{bmatrix} d_1\,\mathbf{a}_1 \\ d_2\,\mathbf{a}_2 \\ d_3\,\mathbf{a}_3 \end{bmatrix} \]

Two identities hold for any such \(\mathbf{D}\):

\[ \begin{aligned} (\mathbf{D}\mathbf{A})\,\mathbf{B} &= \mathbf{D}\,(\mathbf{A}\mathbf{B}) &&\text{(associativity)} \\[4pt] \mathbf{D}\,(\mathbf{X} + \mathbf{Y}) &= \mathbf{D}\mathbf{X} + \mathbf{D}\mathbf{Y} &&\text{(distributivity)} \end{aligned} \]

The first identity follows from the dot-product view of a matrix product. Let \(\mathbf{b}_1, \ldots, \mathbf{b}_p\) be the columns of \(\mathbf{B}\). Entry (i, j) of \(\mathbf{C} = \mathbf{A}\mathbf{B}\) is \(c_{ij} = \mathbf{a}_i \cdot \mathbf{b}_j\). Scaling row i of \(\mathbf{A}\) scales that dot product:

\[ (d_i\,\mathbf{a}_i) \cdot \mathbf{b}_j \;=\; d_i\,(\mathbf{a}_i \cdot \mathbf{b}_j) \;=\; d_i\,c_{ij} \]

Together with Fact 2, the identities give a corollary. Suppose every block in row strip i of \(\mathbf{A}\) is due the same row scaling \(\mathbf{D}\). Scaling the accumulated sum once does the same job:

\[ \sum_k \big(\mathbf{D}\,\mathbf{A}_{ik}\big)\,\mathbf{B}_{kj} \;=\; \mathbf{D} \sum_k \mathbf{A}_{ik}\,\mathbf{B}_{kj} \]

In PyTorch, \(\mathbf{D}\mathbf{X}\) is d[:, None] * X.

The rule covers row scaling only. A column scaling \(\mathbf{A}\mathbf{D}\) is absorbed by \(\mathbf{B}\), as \((\mathbf{A}\mathbf{D})\mathbf{B} = \mathbf{A}(\mathbf{D}\mathbf{B})\), and cannot move to the output.

Attention on blocks of Q, K and V

Cut Q into Q blocks \(\mathbf{Q}_i\) of Br rows, and cut K and V into K/V blocks \(\mathbf{K}_j, \mathbf{V}_j\) of Bc rows. A Br×Bc piece of S or P is a tile. One step of the loop takes Q block i and K/V block j.

1. Scores

\[ \underbrace{\mathbf{S}_{ij}}_{B_r\times B_c} = \underbrace{\mathbf{Q}_i}_{B_r\times d}\,\underbrace{\mathbf{K}_j^\top}_{d\times B_c} \]

Each row of the tile holds Bc of that query's N scores (Fact 2. Block matmul and tiling).

2. Partial softmax

\[ \underbrace{\tilde m_{ij}}_{B_r} = \operatorname{rowmax}(\mathbf{S}_{ij}), \quad \underbrace{\tilde{\mathbf{P}}_{ij}}_{B_r\times B_c} = \exp\big(\mathbf{S}_{ij} - \tilde m_{ij}\big), \quad \underbrace{\tilde\ell_{ij}}_{B_r} = \operatorname{rowsum}(\tilde{\mathbf{P}}_{ij}) \]

\(\tilde{\mathbf{P}}_{ij}\) holds partial softmax scores. Each row is exponentiated against the tile's own max and is not yet normalized, so it differs from the same row of the true Pij by one scalar (Fact 1. Online softmax).

3. Partial sum of the output

\[ \underbrace{\tilde{\mathbf{O}}_{ij}}_{B_r\times d} = \underbrace{\tilde{\mathbf{P}}_{ij}}_{B_r\times B_c}\,\underbrace{\mathbf{V}_j}_{B_c\times d} \]

\(\tilde{\mathbf{O}}_{ij}\) has the shape of Oi. With the true Pij in place of \(\tilde{\mathbf{P}}_{ij}\), these partial sums add up to the output:

\[ \underbrace{\mathbf{O}_i}_{B_r\times d} = \sum_{j=1}^{T_c} \underbrace{\mathbf{P}_{ij}}_{B_r\times B_c}\,\underbrace{\mathbf{V}_j}_{B_c\times d} \]

The sum runs over K/V blocks, so a loop over j can accumulate it (Fact 2. Block matmul and tiling).

4. Merge the row statistics

\[ \underbrace{m_i^{\text{new}}}_{B_r} = \max\big(m_i, \tilde m_{ij}\big), \qquad \underbrace{\ell_i^{\text{new}}}_{B_r} = e^{m_i - m_i^{\text{new}}}\,\ell_i + e^{\tilde m_{ij} - m_i^{\text{new}}}\,\tilde\ell_{ij} \]

The running vectors mi and ℓi absorb the tile's row statistics (Fact 1. Online softmax).

5. Accumulate the output

\[ \underbrace{\mathbf{O}_i}_{B_r\times d} \;\leftarrow\; \mathbf{W}_{\text{old}}\,\mathbf{O}_i \;+\; \mathbf{W}_{\text{new}}\,\tilde{\mathbf{O}}_{ij} \]

\(\mathbf{W}_{\text{old}}\) and \(\mathbf{W}_{\text{new}}\) are row scalings built from the old and new statistics. One row scaling of Oi corrects every partial sum added so far (Fact 3. Row scaling).

§6

Algorithm 1: the tiled forward pass

Algorithm 1 turns the §5 update into a loop over all Q blocks and K/V blocks. There are Tr = ⌈N/Br⌉ Q blocks and Tc = ⌈N/Bc⌉ K/V blocks. The block sizes let one step's working set fit in an SRAM of size M:

\[ B_c = \left\lceil \frac{M}{4d} \right\rceil, \qquad B_r = \min\!\left(\left\lceil \frac{M}{4d} \right\rceil,\; d\right) \]

The factor 4 reserves room for four blocks of about B×d each: Kj, Vj, Qi and Oi. The cap Br ≤ d keeps the S tile Sij, of size Br×Bc ≤ M/4, within SRAM too.

Algorithm 1 FlashAttention. Q, K, V ∈ ℝN×d in HBM, on-chip SRAM of size M. Highlighted lines run entirely in SRAM.
Set block sizes Bc = ⌈M/4d⌉, Br = min(⌈M/4d⌉, d). Initialize O = (0)N×d, ℓ = (0)N, m = (−∞)N in HBM. Divide Q into Tr = ⌈N/Br⌉ blocks Qi (Br×d); divide K, V into Tc = ⌈N/Bc⌉ blocks Kj, Vj (Bc×d). Divide O into Tr blocks Oi, and ℓ, m into Tr blocks ℓi, mi of size Br. for 1 ≤ j ≤ Tc do // outer loop over K/V blocks Load Kj, Vj from HBM to on-chip SRAM. for 1 ≤ i ≤ Tr do // inner loop over Q blocks Load Qi, Oi, ℓi, mi from HBM to on-chip SRAM. Sij = QiKjᵀ ∈ ℝBr×Bc m̃ij = rowmax(Sij), P̃ij = exp(Sij − m̃ij), ℓ̃ij = rowsum(P̃ij) minew = max(mi, m̃ij), ℓinew = emi−minewℓi + em̃ij−minewℓ̃ij Write Oi ← diag(ℓinew)−1(diag(ℓi)emi−minewOi + em̃ij−minewP̃ijVj) to HBM. Write ℓi ← ℓinew, mi ← minew to HBM. end for end for Return O.

Lines 10 and 11 run online softmax on every row of the tile. Each row keeps its own scalars, so mi, ℓi, m̃ij and ℓ̃ij are vectors in ℝBr. In line 12, diag(x) multiplies row r of the matrix beside it by the scalar xr.

Line 12 adds one partial sum to Oi

Tiling splits Oi into one partial sum per K/V block, and the loop over j adds them in order.

Each step adds the provisional term P̃ijVj and rescales the rows of Oi. For row r of the Q block, define:

SymbolShapeMeaning for row r
\(\mathbf{o}\)1 × drow r of Oi, the running output
\(\tilde p_c\)scalarentry c of row r of P̃ij, for c = 1 … Bc
\(\mathbf{v}_c\)1 × drow c of Vj
\(m,\ \ell\)scalarentry r of mi and ℓi, before this step
\(\tilde m\)scalarentry r of m̃ij, the row's max inside this tile
\(m^{\text{new}},\ \ell^{\text{new}}\)scalarentry r of the merged statistics from line 11

For row r, line 12 becomes:

\[ \mathbf{o} \;\leftarrow\; \frac{1}{\ell^{\text{new}}}\Big(\, \ell\, e^{m - m^{\text{new}}}\;\mathbf{o} \;+\; e^{\tilde m - m^{\text{new}}} \sum_{c=1}^{B_c} \tilde p_c\, \mathbf{v}_c \Big) \]

The sum is row r of P̃ijVj: the Bc value rows, weighted by the provisional weights. Collecting the scalars gives two weights:

\[ \underbrace{\mathbf{o}}_{1\times d} \;\leftarrow\; \underbrace{w_{\text{old}}}_{\text{scalar}}\;\underbrace{\mathbf{o}}_{1\times d} \;+\; \underbrace{w_{\text{new}}}_{\text{scalar}}\;\underbrace{\sum_{c=1}^{B_c} \tilde p_c\, \mathbf{v}_c}_{1\times d} \] \[ w_{\text{old}} = \frac{\ell\, e^{m - m^{\text{new}}}}{\ell^{\text{new}}}, \quad w_{\text{new}} = \frac{e^{\tilde m - m^{\text{new}}}}{\ell^{\text{new}}} \]

Every row of the Q block runs this update with its own pair of weights. Those pairs are the two row scalings in the §5 update.

The weight \(w_{\text{old}}\) does three things to the row. Multiplying by ℓ undoes the old normalization. Multiplying by \(e^{m - m^{\text{new}}}\) moves the row to the new reference max. Dividing by \(\ell^{\text{new}}\) normalizes by the new total. The weight \(w_{\text{new}}\) moves the new term to the shared max and normalizes it.

After the last K/V block, Oi equals \(\operatorname{softmax}(\mathbf{S}_i)\,\mathbf{V}\) exactly.

  • Every step rescales all of Oi. The rescale costs Br·d multiplications. The matmul P̃ijVj in the same step costs 2·Br·Bc·d FLOPs, about 2Bc times more.
  • Every step moves Oi through HBM. Line 12 writes Oi out, and line 8 reads it back on the next visit.
  • Every step depends on the previous one. For a fixed i, the j steps run in order, because each needs the mi and ℓi left by the last. The paper parallelizes across (batch, head) pairs instead, one thread block per head.
Old S tiles are discarded

When S13 arrives, S11 and S12 are not rescaled, because they no longer exist. Each S tile is computed in SRAM, used and discarded. Its contribution survives only inside Oi and the row statistics mi and ℓi. The rescale acts on those. Keeping old tiles for later rescaling would mean storing the N×N matrix.

§7

A reference implementation in PyTorch

This plain PyTorch loop implements Algorithm 1, with each slice standing in for a load into SRAM. It runs slowly, because PyTorch launches a kernel per line. In 32-bit floating point (fp32), it matches softmax(QKᵀ/√d)V to about 2×10−7. The test used N = 1000 and d = 64, so the blocks need not divide N evenly.

import torch

def flash_attention_forward(Q, K, V, Br=64, Bc=64):
    """Algorithm 1 in plain PyTorch. Q, K, V: (N, d)."""
    N, d = Q.shape
    O = torch.zeros_like(Q)                 # output, lives in "HBM"
    l = torch.zeros(N)                      # running softmax denominators
    m = torch.full((N,), -float("inf"))     # running row maxima
    scale = d ** -0.5

    for j in range(0, N, Bc):               # outer loop: K/V blocks
        Kj, Vj = K[j:j+Bc], V[j:j+Bc]       # "load K_j, V_j into SRAM"
        for i in range(0, N, Br):           # inner loop: Q blocks
            Qi, Oi = Q[i:i+Br], O[i:i+Br]
            li, mi = l[i:i+Br], m[i:i+Br]

            Sij = scale * Qi @ Kj.T                  # (Br, Bc) tile, never stored
            mij = Sij.max(dim=1).values              # block row max   m~
            Pij = torch.exp(Sij - mij[:, None])      # P~
            lij = Pij.sum(dim=1)                     # block row sum   l~

            mi_new = torch.maximum(mi, mij)
            li_new = torch.exp(mi - mi_new) * li + torch.exp(mij - mi_new) * lij

            O[i:i+Br] = (                             # rescale old, add new, renormalize
                (li * torch.exp(mi - mi_new))[:, None] * Oi
                + torch.exp(mij - mi_new)[:, None] * (Pij @ Vj)
            ) / li_new[:, None]
            l[i:i+Br], m[i:i+Br] = li_new, mi_new
    return O

# check against the naive version
torch.manual_seed(0)
Q, K, V = (torch.randn(1000, 64) for _ in range(3))
ref = torch.softmax(Q @ K.T / 8.0, dim=-1) @ V
print((flash_attention_forward(Q, K, V) - ref).abs().max())   # tensor(1.7881e-07)

The first iteration needs no special case. With m = −∞ and ℓ = 0, the factor exp(mi - mi_new) is 0, so the old-output term vanishes. A real kernel runs the inner-loop body as one program on one SM, holding Sij and Pij in registers and SRAM.

§8

The backward pass recomputes attention tiles

Let L be the training loss, and let dX denote the gradient \(\frac{\partial L}{\partial \mathbf{X}}\) for any tensor X. Training needs dQ, dK and dV, given dO. With \(\mathbf{O} = \mathbf{PV}\) and \(\mathbf{P} = \operatorname{softmax}(\mathbf{S})\), the chain rule gives:

\[ \begin{aligned} d\mathbf{V} &= \mathbf{P}^\top d\mathbf{O}, &\qquad d\mathbf{P} &= d\mathbf{O}\,\mathbf{V}^\top, \\[4pt] dS_{ij} &= P_{ij}\big(dP_{ij} - D_i\big), &\qquad D_i &= \sum_k P_{ik}\, dP_{ik}, \\[4pt] d\mathbf{Q} &= d\mathbf{S}\,\mathbf{K}, &\qquad d\mathbf{K} &= d\mathbf{S}^\top \mathbf{Q} \end{aligned} \]

Here \(S_{ij}\), \(P_{ij}\) and their gradients are single entries, and Di is one scalar per row. The appendix derives dS and Di.

Recomputation replaces the stored P

The standard backward pass reads the N×N matrix P saved by the forward pass. It also writes the N×N gradients dP and dS to HBM and reads them back. FlashAttention saves only O, the row statistics m and ℓ, and the dropout random seed. It recomputes each S tile and P tile in SRAM from Q, K, m and ℓ. The tiles of dP and dS also live only in SRAM. This is gradient checkpointing applied inside one kernel.

The savings are in memory and HBM traffic. Extra memory per head drops from O(N²) to O(N). The recomputation adds FLOPs, yet the backward pass runs faster, because it moves far less data through HBM.

As defined, Di is a dot product of two length-N rows, of P and dP. The paper rewrites it as a dot product of two length-d rows, of dO and O:

\[ D_i \;=\; \sum_k P_{ik}\,(d\mathbf{o}_i^\top \mathbf{v}_k) \;=\; d\mathbf{o}_i^\top \sum_k P_{ik}\mathbf{v}_k \;=\; d\mathbf{o}_i^\top \mathbf{o}_i \]

So \(\mathbf{D} = \operatorname{rowsum}(d\mathbf{O} \circ \mathbf{O})\) costs one N×d elementwise product and no N×N matrix.

Gradients on blocks

The backward pass cuts every N×d matrix into the same row strips as the forward pass. Qi, Oi, dOi and dQi are Br×d, and Kj, Vj, dKj and dVj are Bc×d. The row statistics mi, ℓi and Di have length Br.

Each gradient block is a sum over one block index (Fact 2. Block matmul and tiling):

\[ \underbrace{d\mathbf{V}_j}_{B_c\times d} = \sum_i \underbrace{\mathbf{P}_{ij}^\top}_{B_c\times B_r}\,\underbrace{d\mathbf{O}_i}_{B_r\times d}, \qquad \underbrace{d\mathbf{K}_j}_{B_c\times d} = \sum_i \underbrace{d\mathbf{S}_{ij}^\top}_{B_c\times B_r}\,\underbrace{\mathbf{Q}_i}_{B_r\times d}, \qquad \underbrace{d\mathbf{Q}_i}_{B_r\times d} = \sum_j \underbrace{d\mathbf{S}_{ij}}_{B_r\times B_c}\,\underbrace{\mathbf{K}_j}_{B_c\times d} \]

The outer loop runs over K/V blocks j, as in Algorithm 1. dKj and dVj sum over the inner index i, so they stay in SRAM for the whole inner loop and reach HBM once. dQi sums over the outer index j, so it returns to HBM after every visit, as Oi does in the forward pass.

One step of the inner loop takes Q block i and K/V block j.

1. Recompute the tile

\[ \underbrace{\mathbf{S}_{ij}}_{B_r\times B_c} = \mathbf{Q}_i\mathbf{K}_j^\top, \qquad \underbrace{\mathbf{P}_{ij}}_{B_r\times B_c} = \operatorname{diag}(\ell_i)^{-1} \exp\big(\mathbf{S}_{ij} - m_i\big) \]

The saved mi and ℓi are the final row statistics, so this Pij is exact. It needs no online-softmax rescaling.

2. Value gradient

\[ \underbrace{d\mathbf{V}_j}_{B_c\times d} \;\leftarrow\; d\mathbf{V}_j + \underbrace{\mathbf{P}_{ij}^\top}_{B_c\times B_r}\,\underbrace{d\mathbf{O}_i}_{B_r\times d} \]

Each Q block adds one term of the sum for dVj.

3. Probability and score gradients

\[ \underbrace{d\mathbf{P}_{ij}}_{B_r\times B_c} = \underbrace{d\mathbf{O}_i}_{B_r\times d}\,\underbrace{\mathbf{V}_j^\top}_{d\times B_c}, \qquad \underbrace{D_i}_{B_r} = \operatorname{rowsum}\big(d\mathbf{O}_i \circ \mathbf{O}_i\big) \] \[ \underbrace{d\mathbf{S}_{ij}}_{B_r\times B_c} = \mathbf{P}_{ij} \circ \big(d\mathbf{P}_{ij} - D_i\big) \]

Di needs only the rows of dO and O in Q block i, so dSij needs no other tile.

4. Query and key gradients

\[ \underbrace{d\mathbf{Q}_i}_{B_r\times d} \;\leftarrow\; d\mathbf{Q}_i + \underbrace{d\mathbf{S}_{ij}}_{B_r\times B_c}\,\underbrace{\mathbf{K}_j}_{B_c\times d}, \qquad \underbrace{d\mathbf{K}_j}_{B_c\times d} \;\leftarrow\; d\mathbf{K}_j + \underbrace{d\mathbf{S}_{ij}^\top}_{B_c\times B_r}\,\underbrace{\mathbf{Q}_i}_{B_r\times d} \]

Each update adds one term of its block sum.

Backward pass (simplified from the paper's Algorithm 4).
for each K/V block j do Load Kj, Vj; set dKj = dVj = 0 on-chip. for each Q block i do Load Qi, Oi, dOi, dQi, ℓi, mi. Sij = QiKjᵀ; Pij = diag(ℓi)−1 exp(Sij − mi) // recompute dVj += Pijᵀ dOi; dPij = dOi Vjᵀ Di = rowsum(dOi ∘ Oi); dSij = Pij ∘ (dPij − Di) dQi += dSij Kj → write dQi to HBM dKj += dSijᵀ Qi Write dKj, dVj to HBM.

The paper's Theorem 5 counts the backward pass's HBM accesses: Θ(Nd + N²) for standard attention and Θ(N²d²/M) for FlashAttention. Dropout works the same way as P: the forward pass stores the random seed, and the backward pass regenerates the mask.

§9

IO complexity

The paper's main theoretical result counts the elements moved between HBM and SRAM. It assumes an SRAM of size M, with d ≤ M ≤ Nd.

Theorem 2

Standard attention requires Θ(Nd + N²) HBM accesses, while FlashAttention requires Θ(N²d²M⁻¹) HBM accesses.

Proof sketch

  1. Reading K and V costs Θ(Nd), because each block loads once.
  2. Streaming Q and O costs Θ(Nd) per outer iteration, and there are Tc of them.
  3. Summing gives Θ(Tc·Nd) = Θ((N/Bc)·Nd). With Bc = Θ(M/d), that is Θ(N²d²/M).

The ratio of the two costs is d²/M. With d = 64, d² is 4096, while an A100 SM's SRAM holds about 100K fp16 elements. So d²/M is well below 1, and FlashAttention needs many times fewer HBM accesses. A larger SRAM or smaller head dimension widens the gap.

Proposition 3 · lower bound

No exact attention algorithm can asymptotically beat Θ(N²d²M⁻¹) HBM accesses for all SRAM sizes M in [d, Nd]. FlashAttention's IO cost is therefore optimal up to constants across that range.

§10

Block-sparse FlashAttention

Tiling makes sparsity cheap: the loop skips unneeded tiles. A block mask \(\tilde{\mathbf{M}} \in \{0,1\}^{N/B_r \times N/B_c}\) marks which (i, j) pairs to compute. If a fraction s of the tiles is nonzero, the cost is:

\[ \text{HBM accesses} = \Theta\!\left(Nd + N^2 d^2 M^{-1} s\right) \]

Common patterns have s near N−1/2 or N−1log N, giving Θ(N√N) or Θ(N log N). The paper uses a fixed butterfly pattern. Block-sparse FlashAttention is the paper's only approximate method.

Appendix

The softmax gradient

Show the derivation

Vector form

Let \(\mathbf{s} \in \mathbb{R}^n\) be a vector of scores, and let \(\mathbf{p} = \operatorname{softmax}(\mathbf{s})\). Entry i of the output is

\[ p_i = \frac{e^{s_i}}{Z}, \qquad Z = \sum_{k=1}^{n} e^{s_k} . \]

The Jacobian of softmax is the n×n matrix \(\mathbf{J}\) whose (i, j) entry is \(\frac{\partial p_i}{\partial s_j}\). Row i belongs to output \(p_i\), and column j to input \(s_j\).

Product rule

Write \(p_i\) as the product of \(e^{s_i}\) and \(1/Z\). The product rule, \(\frac{\partial (uv)}{\partial s_j} = \frac{\partial u}{\partial s_j}\, v + u\, \frac{\partial v}{\partial s_j}\), splits the derivative into two parts:

\[ \frac{\partial p_i}{\partial s_j} \;=\; \underbrace{\frac{\partial e^{s_i}}{\partial s_j}}_{\text{part 1}}\cdot \frac{1}{Z} \;+\; e^{s_i} \cdot \underbrace{\frac{\partial}{\partial s_j}\Big(\frac{1}{Z}\Big)}_{\text{part 2}} \]

Part 1: the numerator \(e^{s_i}\)

The derivative depends on whether the output index i equals the input index j:

\[ \frac{\partial e^{s_i}}{\partial s_j} = \begin{cases} e^{s_i}, & i = j, \\[2pt] 0, & i \ne j . \end{cases} \]

For \(i = j\), the derivative of \(e^{x}\) is \(e^{x}\). For \(i \ne j\), \(e^{s_i}\) does not depend on \(s_j\). The Kronecker delta \(\delta_{ij}\) is 1 for \(i = j\) and 0 otherwise, so it writes both branches as one formula:

\[ \frac{\partial e^{s_i}}{\partial s_j} = \delta_{ij}\, e^{s_i} \]

Part 2: the reciprocal \(1/Z\)

The chain rule \(\frac{dy}{dx} = \frac{dy}{du}\,\frac{du}{dx}\) applies with \(y = 1/Z\), \(u = Z\) and \(x = s_j\):

\[ \frac{dy}{du} = -\frac{1}{Z^2}, \qquad \frac{du}{dx} = \frac{\partial Z}{\partial s_j} = \sum_{k=1}^{n} \frac{\partial e^{s_k}}{\partial s_j} = \sum_{k=1}^{n} \delta_{kj}\, e^{s_k} = e^{s_j} \]

In \(\frac{du}{dx}\), part 1 gives each term \(\frac{\partial e^{s_k}}{\partial s_j} = \delta_{kj}\, e^{s_k}\), which is zero except for k = j. Multiplying the two factors gives

\[ \frac{\partial}{\partial s_j}\Big(\frac{1}{Z}\Big) = -\frac{e^{s_j}}{Z^2} . \]

Combine the parts

\[ \frac{\partial p_i}{\partial s_j} \;=\; \delta_{ij}\, e^{s_i} \cdot \frac{1}{Z} \;-\; e^{s_i} \cdot \frac{e^{s_j}}{Z^2} \;=\; \delta_{ij}\,\frac{e^{s_i}}{Z} - \frac{e^{s_i}}{Z}\,\frac{e^{s_j}}{Z} \;=\; \delta_{ij}\, p_i - p_i\, p_j . \]
\[ \frac{\partial p_i}{\partial s_j} = p_i\,\big(\delta_{ij} - p_j\big), \qquad \mathbf{J} = \operatorname{diag}(\mathbf{p}) - \mathbf{p}\,\mathbf{p}^\top \]

The Jacobian is symmetric: entry (i, j) and entry (j, i) both equal \(\delta_{ij}\,p_i - p_i\,p_j\).

Every output \(p_i\) depends on \(s_j\), so the chain rule sums over i:

\[ \frac{\partial L}{\partial s_j} \;=\; \sum_{i=1}^{n} \frac{\partial L}{\partial p_i}\,\frac{\partial p_i}{\partial s_j} \;=\; \sum_{i=1}^{n} \frac{\partial L}{\partial p_i}\, p_i\big(\delta_{ij} - p_j\big) \;=\; p_j\,\frac{\partial L}{\partial p_j} - p_j \sum_{i=1}^{n} p_i\,\frac{\partial L}{\partial p_i} . \]

The sum \(\sum_i p_i\,\frac{\partial L}{\partial p_i} = \mathbf{p}^\top \frac{\partial L}{\partial \mathbf{p}}\) is one scalar, shared by every entry j. In vector form:

\[ \frac{\partial L}{\partial \mathbf{s}} \;=\; \mathbf{p} \circ \Big(\frac{\partial L}{\partial \mathbf{p}} - \Big(\mathbf{p}^\top \frac{\partial L}{\partial \mathbf{p}}\Big)\,\mathbf{1}\Big) \]

Matrix form

Softmax acts on each row of \(\mathbf{S} \in \mathbb{R}^{N\times N}\) on its own. Row i of P depends only on row i of S, so the vector form applies to each row with \(\mathbf{s} = \mathbf{s}_i\) and \(\mathbf{p} = \mathbf{p}_i\). Index i now names the row, so entry j of the vector form becomes column j, and the summation index becomes k. In the dX notation of §8, \(dS_{ij} = \frac{\partial L}{\partial S_{ij}}\) and \(dP_{ij} = \frac{\partial L}{\partial P_{ij}}\):

\[ dS_{ij} = P_{ij}\big(dP_{ij} - D_i\big), \qquad D_i = \mathbf{p}_i^\top d\mathbf{p}_i = \sum_{k=1}^{N} P_{ik}\, dP_{ik} \]

With \(\mathbf{D} \in \mathbb{R}^N\) collecting the \(D_i\), the whole matrix is

\[ d\mathbf{S} = \mathbf{P} \circ \big(d\mathbf{P} - \mathbf{D}\,\mathbf{1}^\top\big), \qquad \mathbf{D} = \operatorname{rowsum}\big(\mathbf{P} \circ d\mathbf{P}\big) . \]

Di from dO and O

Di is a scalar: the dot product of row i of P with row i of dP, both of length N. Two facts from the forward pass rewrite it. Entry (i, k) of \(d\mathbf{P} = d\mathbf{O}\,\mathbf{V}^\top\) is a dot product of length d, and row i of \(\mathbf{O} = \mathbf{P}\mathbf{V}\) is a weighted sum of value rows:

\[ dP_{ik} = d\mathbf{o}_i^\top \mathbf{v}_k, \qquad \mathbf{o}_i = \sum_{k=1}^{N} P_{ik}\,\mathbf{v}_k . \]

Here \(d\mathbf{o}_i\), \(\mathbf{o}_i\) and \(\mathbf{v}_k\) are rows of dO, O and V, each of length d. Substituting the first fact and pulling \(d\mathbf{o}_i\) out of the sum gives the second:

\[ D_i \;=\; \sum_{k=1}^{N} P_{ik}\,\big(d\mathbf{o}_i^\top \mathbf{v}_k\big) \;=\; d\mathbf{o}_i^\top \Big(\sum_{k=1}^{N} P_{ik}\,\mathbf{v}_k\Big) \;=\; d\mathbf{o}_i^\top \mathbf{o}_i \]

The length-N dot product over P and dP becomes a length-d dot product over dO and O. For all rows at once, \(\mathbf{D} = \operatorname{rowsum}(d\mathbf{O} \circ \mathbf{O})\).
